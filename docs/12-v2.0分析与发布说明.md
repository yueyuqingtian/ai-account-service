# v2.0 分析与发布说明

## 1. v1.0 复盘

v1.0 已经完成可演示主链路，但仍主要是 MVP 形态：

- 支付渠道逻辑散落在 Controller 中
- 支付宝、微信支付只有入口字段，缺少配置状态检查
- 库存密码以开发明文形态写入
- 未支付订单不会自动关闭
- 缺少后端测试依赖和基础测试
- 缺少容器化部署入口
- 用户端创建支付后自动模拟成功，流程过快
- 管理后台不能查看支付配置就绪状态

## 2. v2.0 目标

v2.0 从“能演示”推进到“更接近可部署、可维护、可继续扩展”的工程版本。

核心目标：

- 支付渠道抽象出来
- 敏感库存数据加密
- 订单状态自动维护
- 前端支付流程更明确
- 后台运营信息更完整
- 构建、测试、部署入口补齐

## 3. 本次新增能力

后端：

- 新增 `PaymentGatewayService`
- 支持 `MOCK`、`ALIPAY`、`WECHAT` 三类支付渠道统一建单结果
- 新增支付配置状态接口：`GET /admin/payment-config`
- 支付创建支持复用同订单同渠道未完成支付单
- Token 密钥改为配置化：`GPT_PLUS_TOKEN_SECRET`
- 新增 `CryptoService`，库存密码支持 AES 加密
- 库存导入时写入密文
- 兑换成功时解密返回交付密码
- 新增未支付订单定时关闭任务
- 新增后端测试依赖、上下文测试和加解密测试
- 新增 Dockerfile 和 docker-compose.yml

用户端：

- 商品详情页支付流程升级
- 创建订单和支付后展示待支付信息
- 支持展示支付单号、渠道、支付类型、支付地址
- 用户明确点击“模拟支付成功”后完成发卡
- 我的权益页增加刷新入口
- 兑换输入框增加自动 trim

管理后台：

- 新增支付配置页面
- 展示 Mock、支付宝、微信支付配置状态
- 支付敏感配置脱敏展示
- 订单与记录页增加关键字搜索和刷新查询

## 5. 当前版本边界

- 支付宝、微信支付已具备适配服务和配置就绪检查，但未接真实 SDK 下单与验签
- 本地开发仍使用 H2，生产使用 PostgreSQL 配置和 `sql/init_schema.sql`
- 后台权限仍是管理员级别，未细分到按钮级角色权限
- 库存密码使用应用层 AES，生产建议对接 KMS 或云密钥管理
- Docker Compose 当前覆盖后端和 PostgreSQL，前端生产镜像可在下一版补齐

## 6. 下一版建议

- 接入支付宝官方 SDK
- 接入微信支付 API v3 SDK
- 增加真实回调验签
- 增加退款与对账
- 增加后台角色权限矩阵
- 增加前端生产 Docker 镜像
- 增加 Playwright 端到端测试
- 增加 PostgreSQL Testcontainers 集成测试
