# 项目总览与技术选型

## 1. 项目定位

本项目面向“虚拟权益/CDKey 售卖与兑换”场景，提供一套从商品展示、订单支付、卡密发放、权益兑换到后台运营管理的完整系统方案。

系统按双端拆分：

- 用户端：负责商品浏览、下单、支付、查看订单、查看 CDKey、发起兑换
- 管理后台：负责商品管理、订单管理、支付监控、库存导入、CDKey 管理、兑换记录追踪

## 2. 目标能力

### 用户侧

- 注册与登录
- 商品列表与详情浏览
- 订单创建与支付
- 查看订单与卡密
- CDKey 兑换
- 查看兑换结果与售后说明

### 平台侧

- 商品上下架与定价
- 订单状态流转与支付回调处理
- CDKey 生成、绑定、核销
- 账号库存导入、分配、冻结
- 风控拦截与日志审计
- 数据统计与运营报表

## 3. 技术栈选择

## 3.1 后端

- Java 21
- Spring Boot 3.3.x
- Spring Security
- MyBatis-Plus
- Spring Validation
- Redis
- PostgreSQL / Render Postgres
- Sa-Token 不采用，统一使用 Spring Security + JWT
- OpenAPI 3 用于接口文档导出

## 3.2 前端用户端

- Vue 3
- Vite 5
- TypeScript
- Pinia
- Vue Router
- Axios
- UnoCSS 或 TailwindCSS 二选一，本方案推荐 UnoCSS

## 3.3 前端管理后台

- Vue 3
- Vite 5
- TypeScript
- Pinia
- Vue Router
- Element Plus
- Axios
- ECharts

## 3.4 基础设施

- Nginx 作为反向代理
- Docker 用于部署
- GitHub Actions 或 Jenkins 用于 CI/CD
- MinIO 或云对象存储用于商品图与凭证图

## 4. 为什么这样选型

- Spring Boot 适合订单、支付、库存、风控这类事务型强的业务
- MyBatis-Plus 能降低 CRUD 成本，同时保留复杂 SQL 可控性
- Redis 可承载兑换锁、支付幂等、验证码、限流等需求
- Vue 3 全栈统一前端技术，用户端与后台端共享部分请求层和类型定义
- Element Plus 能快速支撑中后台页面建设

## 5. 系统拆分建议

建议按单体优先、领域清晰分层的方式启动，避免初期过早微服务化。

### 后端模块划分

- `auth`：用户认证与权限
- `user`：用户资料与风控标签
- `product`：商品、价格、展示
- `order`：订单创建、关闭、查询
- `payment`：支付创建、回调、对账
- `cdkey`：卡密生成、绑定、核销
- `inventory`：账号库存导入、锁定、分配
- `redeem`：兑换流程编排
- `admin`：后台统计与管理接口
- `audit`：日志审计与追踪

### 前端应用拆分

- `apps/web`：用户端
- `apps/admin`：管理后台
- `packages/shared`：共享类型、请求封装、通用常量

## 6. 非功能性要求

- 所有支付回调必须幂等
- 所有兑换动作必须防重复提交
- 敏感库存信息必须加密存储
- 关键操作必须可审计
- 核心列表必须支持分页、筛选与导出
- 接口统一返回结构，方便前后端联调

## 7. 交付顺序建议

第一阶段：业务契约与表结构

第二阶段：后端核心链路

第三阶段：用户端页面

第四阶段：管理后台

第五阶段：风控、监控与运维能力
