# 后端工程骨架设计

## 1. 文档目标

本文档用于将《后端系统设计》《数据库设计》《API 契约设计》落到一个可直接初始化的 Spring Boot 工程骨架上，确保后续编码时目录、分层、命名、职责和启动顺序保持一致。

## 2. 工程定位

后端采用：

- `Java 21`
- `Spring Boot 3`
- `Spring Security + JWT`
- `MyBatis-Plus`
- `Redis`
- `PostgreSQL / Render Postgres`

第一阶段采用单体应用，后端目录建议放在仓库根目录下：

- `backend/`

## 4. 包结构落地原则

顶层按领域拆包，领域内再按职责分层。这样可以同时满足：

- 模块边界清晰
- 业务聚合度高
- 后续扩展成本低
- 避免所有类都堆在 `service`、`mapper` 两层里

## 5. 领域内部分层模板

每个业务域建议采用如下结构：

```text
product
├─ controller
├─ application
├─ dto
├─ vo
├─ domain
│  ├─ entity
│  ├─ enums
│  ├─ service
│  └─ repository
├─ infrastructure
│  ├─ dataobject
│  ├─ mapper
│  └─ repositoryimpl
└─ convert
```

说明：

- `controller`：接收 HTTP 请求，做参数校验和响应封装
- `application`：负责编排业务用例和事务边界
- `dto`：请求对象与内部用例入参对象
- `vo`：返回对象
- `domain.entity`：领域实体与核心状态
- `domain.enums`：领域枚举
- `domain.service`：领域规则与业务计算
- `domain.repository`：领域层仓储接口
- `infrastructure.dataobject`：数据库映射对象
- `infrastructure.mapper`：MyBatis-Plus Mapper
- `infrastructure.repositoryimpl`：仓储实现
- `convert`：DTO、DO、VO、Entity 之间转换

## 8. 控制器分组约定

用户侧控制器：

- 统一以 `/api` 为前缀

后台侧控制器：

- 统一以 `/admin` 为前缀

回调控制器：

- 建议单独归在 `/api/payments/callback` 或 `/callback/payments`

## 9. DTO、VO、Entity、DO 命名规范

- 请求对象统一使用 `*RequestDTO` 或 `*CommandDTO`
- 返回对象统一使用 `*VO`
- 领域实体统一使用 `*Entity`
- 数据库映射对象统一使用 `*DO`
- Mapper 统一使用 `*Mapper`
- 仓储接口统一使用 `*Repository`
- 仓储实现统一使用 `*RepositoryImpl`

## 11. 统一技术约束

- Controller 不直接调用 Mapper
- 跨领域流程统一放在 `application` 层编排
- 领域规则优先下沉到 `domain.service`
- 枚举值必须与文档和数据库脚本一致
- 所有状态流转必须通过明确方法执行，禁止在代码中随意写字符串硬改状态
- 支付回调、兑换流程、库存分配必须显式定义事务边界
- 敏感信息不得明文日志输出

## 15. 启动阶段里程碑

### M1：骨架启动

目标：

- 后端工程可启动
- 数据源连接正常
- OpenAPI 可访问
- 健康检查接口可访问

### M2：基础认证

目标：

- 注册登录完成
- JWT 校验可用
- 用户态和管理员态路由区分完成

### M3：主链路打通

目标：

- 商品 -> 订单 -> 支付 -> CDKey -> 兑换 全链路贯通

### M4：后台可运营

目标：

- 商品、订单、库存、兑换记录具备基础运营能力

## 16. 与 SQL 脚本的对应关系

后端实体和表结构必须严格对齐以下文件：

- `sql/init_schema.sql`
- `docs/06-数据库设计.md`
- `docs/05-API契约设计.md`

如后续调整字段，必须同步更新这三处，避免前后端与数据库契约漂移。
