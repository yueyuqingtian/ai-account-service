# 前端用户端设计

## 1. 目标

用户端负责承接从访问首页到完成兑换的完整购买链路，核心目标是转化清晰、流程可控、状态反馈完整。

## 2. 页面结构

```text
<App>
  -> <WebLayout>
    -> <HomePage>
    -> <ProductDetailPage>
    -> <CheckoutPage>
    -> <PayResultPage>
    -> <UserCenterPage>
       -> <OrderListTab>
       -> <CdkeyListTab>
       -> <RedeemRecordTab>
    -> <RedeemPage>
    -> <LoginPage>
```

## 3. 路由设计

- `/`：首页
- `/product/:id`：商品详情
- `/checkout/:productId`：下单页
- `/pay/result`：支付结果页
- `/login`：登录页
- `/user/orders`：我的订单
- `/user/cdkeys`：我的卡密
- `/user/redeems`：我的兑换记录
- `/redeem`：兑换中心

## 4. 页面职责

## 4.1 首页

展示内容：

- 商品卡片列表
- 优势说明
- 购买流程说明
- 常见问题

交互要求：

- 支持跳转商品详情
- 支持显示商品状态

## 4.2 商品详情页

展示内容：

- 商品封面
- 商品标题
- 售价与划线价
- 购买须知
- 交付方式
- 风险提示

交互要求：

- 未登录点击购买时引导登录
- 下架商品不可购买

## 4.3 下单页

展示内容：

- 商品摘要
- 实付金额
- 支付方式
- 提交订单按钮

状态要求：

- 提交中
- 提交失败
- 订单创建成功

## 4.4 支付结果页

展示内容：

- 支付成功或失败状态
- 订单号
- 跳转到订单中心或卡密中心

## 4.5 用户中心

标签页：

- 我的订单
- 我的 CDKey
- 我的兑换记录

表格字段建议：

- 订单号
- 商品名
- 金额
- 状态
- 创建时间
- 操作按钮

## 4.6 兑换中心

表单内容：

- CDKey 输入框
- 兑换按钮
- 兑换须知

结果展示：

- 成功时显示交付信息
- 失败时显示失败原因
- 敏感字段支持点击查看或复制

## 5. 状态管理

Pinia store 建议拆分：

- `useAuthStore`
- `useProductStore`
- `useOrderStore`
- `useCdkeyStore`
- `useRedeemStore`
- `useAppStore`

## 6. 接口层规范

统一封装：

- 请求拦截器注入 token
- 响应拦截器处理统一错误码
- 对登录过期自动跳转

## 7. UI 状态约束

所有核心页面必须处理四态：

- `loading`
- `empty`
- `error`
- `success`

## 8. 组件拆分建议

### 展示型组件

- `ProductCard`
- `StatusTag`
- `PriceBlock`
- `EmptyState`
- `ErrorState`

### 容器型组件

- `ProductListSection`
- `CheckoutPanel`
- `OrderListContainer`
- `RedeemFormContainer`

## 9. 安全与体验要求

- 不在本地持久化敏感交付信息
- 兑换成功后支持再次查看，但需要用户登录态
- 页面按钮必须防重复点击
- 请求失败需给出明确错误提示

## 10. 埋点建议

关键埋点：

- 首页曝光
- 商品详情访问
- 点击购买
- 创建订单成功
- 支付成功
- 卡密兑换成功
- 卡密兑换失败
