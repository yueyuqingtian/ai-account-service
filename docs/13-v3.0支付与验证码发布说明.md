# v3.0 支付与验证码发布说明

## 1. 发布目标

v3.0 在 v2.0 的支付、发卡、兑换闭环基础上，补齐 OpenAI 登录验证码查询能力。

业务假设：

- 用户购买后兑换得到账号邮箱和账号密码
- OpenAI 登录验证码邮件会统一转发到一个 Google 邮箱
- 管理员在后台配置该 Google 邮箱和邮箱应用密钥
- 用户输入自己购买得到的账号邮箱和密码后，可以查询最近验证码
- 后端通过 Gmail IMAP 读取邮件

## 2. 本版新增能力

### 后端

- 新增 `system_config` 表
- 新增 `verification_code_query_log` 表
- 新增后台 Google 邮箱配置接口
- 新增用户端验证码查询接口
- 新增 Gmail IMAP 查询服务
- Gmail 应用密钥加密存储
- 用户查询验证码前会校验账号归属和账号密码
- 验证码查询成功/失败都会写入日志

### 管理后台

- 新增“邮箱配置”页面
- 可配置 Google 邮箱
- 可配置 Google 邮箱应用密钥
- 可配置 IMAP Host 和 Folder
- 记录页新增“验证码日志”

### 用户端

- 顶部导航新增“验证码”
- 新增 OpenAI 登录验证码查询页
- 兑换成功后可跳转验证码查询页
- 用户需输入已购买账号邮箱和账号密码

## 3. 接口

后台：

- `GET /admin/email-config`
- `POST /admin/email-config`

用户端：

- `POST /api/verification-code/query`

请求示例：

```json
{
  "accountEmail": "purchased-account@example.com",
  "accountPassword": "account-password"
}
```

## 4. 安全约束

- Google 邮箱应用密钥使用 `CryptoService` 加密存储
- 用户输入的账号密码只用于校验自己已兑换的库存账号
- 只有账号归属当前用户且密码匹配时，才会发起 IMAP 查询
- 验证码查询日志保留结果、账号、失败原因和验证码值，便于排障

## 5. IMAP 说明

默认配置：

- Host：`imap.gmail.com`
- Port：`993`
- SSL：启用
- Folder：`INBOX`
- 查询范围：最近 30 分钟
- 验证码格式：6 位数字

邮件匹配规则：

- 邮件标题或正文中必须包含用户输入的购买账号邮箱
- 在匹配邮件标题和正文中提取第一个 6 位数字验证码

## 7. 验收路径

1. 打开管理后台
2. 使用目标环境中创建的正式管理员账号登录
3. 进入“邮箱配置”
4. 配置 Google 邮箱和应用密钥
5. 用户端完成购买、支付、兑换
6. 进入“验证码”
7. 输入兑换得到的账号邮箱和账号密码
8. 查询 OpenAI 登录验证码

## 8. 当前边界

- 需要 Google 邮箱开启 IMAP
- 需要使用 Google 邮箱应用密钥，不建议使用主密码
- 如果转发邮件正文中不包含被购买账号邮箱，则无法精准匹配
- 当前提取 6 位数字验证码，其他格式需要后续扩展
