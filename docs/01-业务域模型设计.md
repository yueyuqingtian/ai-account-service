# 业务域模型设计

## 1. 业务概述

系统的核心业务是：用户支付后获取一个可兑换凭证，用户再凭凭证兑换一份可交付的虚拟权益。该权益可以表现为账号密码、卡密、链接、激活码或其他数字资产。

为避免后期耦合，业务上必须拆分以下核心领域对象：

- 商品
- 订单
- 支付单
- CDKey
- 库存资源
- 兑换记录
- 用户
- 风控事件

## 2. 领域边界

## 2.1 商品域 Product

职责：

- 管理售卖对象
- 定义价格、描述、展示信息
- 决定交付方式

关键属性：

- 商品名称
- 商品编码
- 售价
- 原价
- 商品状态
- 交付类型
- 限购规则

## 2.2 订单域 Order

职责：

- 记录用户购买行为
- 管理交易状态
- 关联支付与交付

关键属性：

- 订单号
- 用户 ID
- 商品 ID
- 订单金额
- 支付状态
- 发货状态
- 关闭原因

## 2.3 支付域 Payment

职责：

- 创建支付单
- 接收支付回调
- 执行幂等更新
- 留存第三方回调原文

关键属性：

- 支付单号
- 订单号
- 支付渠道
- 支付金额
- 支付状态
- 第三方流水号
- 回调报文

## 2.4 卡密域 CDKey

职责：

- 表示用户的兑换凭证
- 记录卡密生命周期
- 支持失效、锁定、核销

关键属性：

- 卡密编码
- 所属订单
- 所属商品
- 所属用户
- 卡密状态
- 过期时间
- 使用时间

## 2.5 库存域 Inventory

职责：

- 保存待分配的虚拟资源
- 管理资源状态
- 支持分配、锁定、冻结

关键属性：

- 资源批次号
- 商品 ID
- 账号或资源值
- 密码密文
- 分配状态
- 分配目标用户
- 分配时间

## 2.6 兑换域 Redeem

职责：

- 执行卡密校验
- 调用库存分配逻辑
- 输出交付结果
- 留痕兑换行为

关键属性：

- 兑换编号
- 用户 ID
- 卡密 ID
- 资源 ID
- 兑换结果
- 失败原因
- 客户端信息

## 2.7 风控域 Risk

职责：

- 限流
- 风险评分
- 黑名单校验
- 异常操作预警

关键属性：

- 风险事件类型
- 用户 ID
- IP
- 设备指纹
- 命中策略
- 处理结果

## 3. 核心状态机

## 3.1 订单状态

- `UNPAID`
- `PAID`
- `DELIVERED`
- `COMPLETED`
- `CLOSED`
- `REFUNDED`

状态流转：

`UNPAID -> PAID -> DELIVERED -> COMPLETED`

`UNPAID -> CLOSED`

`PAID -> REFUNDED`

## 3.2 支付状态

- `INIT`
- `PROCESSING`
- `SUCCESS`
- `FAILED`
- `CLOSED`

## 3.3 CDKey 状态

- `UNBOUND`
- `BOUND`
- `USED`
- `EXPIRED`
- `LOCKED`
- `INVALID`

状态流转：

`UNBOUND -> BOUND -> USED`

`BOUND -> EXPIRED`

`BOUND -> LOCKED`

## 3.4 库存状态

- `AVAILABLE`
- `LOCKED`
- `ASSIGNED`
- `DISABLED`
- `RECYCLED`

状态流转：

`AVAILABLE -> LOCKED -> ASSIGNED`

`AVAILABLE -> DISABLED`

## 4. 核心业务规则

- 只有已支付订单才能绑定 CDKey
- 一个订单默认只发放一个 CDKey，后期如支持多份购买，再扩展数量字段
- 一个 CDKey 只能成功兑换一次
- 一个库存资源只能分配给一个最终用户
- 支付回调重复到达时，不得重复发放 CDKey
- 兑换时必须先锁定 CDKey，再锁定库存
- 若库存不足，兑换失败但 CDKey 不自动作废，待补库存后可重试
