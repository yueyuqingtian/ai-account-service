# 实施计划与风控设计

## 1. MVP 实施范围

第一阶段只做最小可用闭环：

- 用户注册登录
- 商品展示
- 订单创建
- 支付创建与回调
- 支付成功后发放 CDKey
- 用户查看 CDKey
- CDKey 兑换
- 后台导入库存
- 后台查看订单与兑换记录

## 2. 分阶段实施计划

## 阶段一：契约与基础设施

输出物：

- 数据库表设计
- API 契约文档
- 后端模块骨架
- 前端应用骨架

## 阶段二：后端核心链路

输出物：

- 登录与鉴权
- 商品接口
- 订单接口
- 支付创建与回调
- CDKey 发放逻辑
- 兑换逻辑

## 阶段三：用户端页面

输出物：

- 首页
- 商品详情页
- 下单页
- 用户中心
- 兑换中心

## 阶段四：管理后台

输出物：

- 仪表盘
- 商品管理
- 订单管理
- CDKey 管理
- 库存导入
- 兑换记录

## 阶段五：稳定性建设

输出物：

- 风控规则
- 告警
- 审计日志
- 运营报表

## 3. 风控设计

## 3.1 用户登录风控

- 登录失败次数阈值控制
- 新设备登录提醒
- 异常 IP 段拦截

## 3.2 下单风控

- 同 IP 高频下单限流
- 同账号短时重复创建订单限制
- 超时未支付订单自动关闭

## 3.3 支付风控

- 支付金额不匹配拒绝入账
- 回调验签失败立即记录告警
- 第三方流水重复回调触发幂等保护

## 3.4 兑换风控

- 同一用户每日兑换次数限制
- 同一 IP 短时间高频兑换限制
- 新注册用户兑换增加二次验证
- 命中高风险规则时人工审核或拒绝

## 3.5 管理后台风控

- 敏感操作二次确认
- 库存导入需记录批次与操作人
- 管理员账号分角色授权

## 4. 核心监控项

- 订单创建成功率
- 支付回调成功率
- 卡密发放成功率
- 兑换成功率
- 库存余量预警
- 接口平均耗时
- 核心错误码分布

## 5. 质量门禁

上线前必须满足：

- 核心业务状态机自洽
- 重复支付回调不重复发货
- 重复兑换请求不重复分配库存
- 前端页面具备 loading、empty、error、success 四态
- 核心后台操作具备日志审计

## 6. 团队协作建议

- 产品先冻结枚举值与状态机
- 前后端先对齐 DTO 与错误码
- 后端优先实现 Swagger/OpenAPI
- 前端在 Mock 数据基础上提前联调页面

- 初始化前端用户端脚手架
- 初始化前端管理后台脚手架

- 先打通商品 -> 订单 -> 支付 -> CDKey -> 兑换主链路
